# Attack evaluation

Generated by `python3 tools/attack_eval.py --write docs/ATTACKS.md`.

| Attack | Caught | By | Why it is caught |
|---|---|---|---|
| baseline: an untouched record | yes | `—` | the record verifies before any attack |
| 1. edit the receipt (decision executed -> observe) | yes | `signature` | envelope signature covers the receipt |
| 2. change the amount the approver saw | yes | `signature` | the signed grant binds the intent commitment |
| 3. swap the inclusion proof (then re-sign as approver) | yes | `inclusion` | proof must reach the signed root |
| 4. forge the witness pin (re-signed bundle) | yes | `witness` | the note is signed by the witness key, not by the builder |
| 5. ship a witness state without a note | yes | `witness` | a claim is not a proof when witness signers are required |
| 6. re-sign the whole bundle with another key | yes | `signature` | the signer must be in the allowed signers file |
| 7. redeem the same grant twice (replay) | yes | `core.redeem` | GrantReplayed: grant already used |
| 8. edit a record inside the hash-chained log | yes | `core.verify_chain` | each entry must hash to its own body |
| 9. drop the last entry (sealed head kept) | yes | `core.verify_chain` | the sealed head no longer matches the last entry |
| 10. rewrite an entry and re-sign the STH with a stolen log key | yes | `inclusion` | the receipt does not sit under the rewritten root (inclusion); the witness note also still pins the original root |

**11/11 attacks caught.**
