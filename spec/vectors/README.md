# Test vectors

Generated by `python3 tools/make_vectors.py`. The key is worthless: it exists so
anyone can run the independent verifier and see both outcomes.

| file | what it is |
|---|---|
| `intent.json` | the effect, who may execute it, the nonce, provenance |
| `grant.json` | the approver's Ed25519 (OpenSSH) signature over `jcs(grant)` |
| `receipt.json` | one ledger entry: `body` plus `hash = sha256(jcs(body))` |
| `allowed_signers` | the principal allowed to sign, in OpenSSH format |
| `intent-tampered.json` | the amount changed to 9999.00 after approval |
| `receipt-tampered.json` | `decision` changed to `allowed`, hash left stale |

## Expected

```bash
python3 spec/verify_offline.py --grant spec/vectors/grant.json \
    --intent spec/vectors/intent.json --signers spec/vectors/allowed_signers \
    --receipt spec/vectors/receipt.json
# ok: true, exit 0

python3 spec/verify_offline.py --grant spec/vectors/grant.json \
    --intent spec/vectors/intent-tampered.json --signers spec/vectors/allowed_signers
# ok: false, exit 1 — "grant commitment does not match the intent"
```

`verify_offline.py` imports no project code and does not call `ssh-keygen`. It
re-implements RFC 8785 canonicalisation, the SSHSIG container and Ed25519 from
the RFCs in about 350 lines of standard-library Python, so a reviewer can read
everything that decides the answer.

What it deliberately does not check: that a nonce was claimed once (needs the
ledger), an RFC 3161 token (needs the TSA certificate), revocation (needs the
revoked file). Those are in `mandate verify`, which is our code — and that is
exactly why this script exists.
